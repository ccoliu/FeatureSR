# Feature-SR 上採樣解析度實驗報告：28×28 vs 56×56
最後更新：2026-09-12

## 背景

延續 `reports/0909_FeatureSR內部Ablation報告.md` 與 `reports/0910_Lambda3敏感度分析報告.md` 的一系列消融/敏感度分析。既然已知 FeatureRefiner（Transformer 精煉層）無效、$\mathcal{L}_{CR}$ 的貢獻是資料集依賴的，下一個自然的問題是：**FeatureUpsampler 本身的上採樣密度**是否是關鍵因素——如果把 14×14 → 28×28（scale=2）進一步提高到 14×14 → 56×56（scale=4），能不能提供更細緻的局部特徵、進一步提升分類準確率？

## 架構確認

`models/feature_sr.py` 的 `scale` 參數本來就是通用設計（docstring 明載 "scale=4 → 56×56"），`FeatureUpsampler` / `FeatureRefiner` / `CrossResolutionConsistencyLoss` 全部用 `scale`/`output_size` 動態計算，不需要修改 CLIP 的位置編碼（那是給另一個已擱置的「448×448 原生影像」實驗用的，跟本實驗是兩回事）。

順帶修正了 `train.py` 兩處寫死 "28x28" 字樣的 log 訊息，改為依 `sr_scale` 動態顯示實際解析度（純 log 修正，不影響訓練邏輯）。

## 方法

`--sr_scale 4 --sr_refiner_layers 0 --lambda3 0.3`，四個資料集全測（EuroSAT、CropDiseases、ISIC、ChestX），per-dataset $\lambda_1, \lambda_2$ 沿用 Table 13 值。5-way 5-shot、400 episodes、`--strict_few_shot`、`lr=1e-4`、無 warmup、`seed=42`，協定與既有 ablation/sweep 一致。

**關掉 Refiner 的理由**：Refiner 的 self-attention 是 $O(P^2)$，56×56=3136 個 patch 會讓其計算量比 28×28=784 個 patch 暴增 16 倍；Cycle Consistency Loss 本身對 patch 數只是線性 $O(P)$，不會爆炸。既然 0909 report 已證明 Refiner 三個資料集上一致無貢獻，關掉它既符合已驗證的架構建議，也避開不必要的平方成本。

**對照組**：scale=2、refiner=0、λ3=0.3（即 0909 ablation report 的 C 組），EuroSAT/CropDiseases/ISIC 已有數字；ChestX 當時未納入 ablation，本次一併補跑。

腳本：`scripts/run_56x56_experiment.sh`。訓練皆在 server127（RTX 4090）完成，無中斷、無崩潰（4 組主實驗 + 1 組 ChestX 對照組，皆完整跑滿 100 epochs）。Log 存於 `logs/56x56_experiment/`。

## 結果

| 資料集 | 28×28（對照組，refiner=0） | 56×56（refiner=0） | Δ | 判定 |
|:---|:---:|:---:|:---:|:---:|
| EuroSAT | 89.96 ± 0.43% | 90.54 ± 0.42% | +0.58pp | 雜訊範圍內（CI 和 0.85pp） |
| CropDiseases | 90.23 ± 0.65% | 89.99 ± 0.66% | -0.24pp | 雜訊範圍內 |
| ISIC 2018 | 43.06 ± 0.64% | 42.17 ± 0.59% | -0.89pp | 雜訊範圍內，偏負向 |
| ChestX | 22.70 ± 0.46% | 22.74 ± 0.46% | +0.04pp | 完全持平（兩者皆雜訊等級） |

**參數量代價**：FeatureUpsampler 的可訓練參數從 scale=2 的 5.92M 增加到 scale=4 的 9.54M（+61%，總可訓練參數含 LoRA 從 6.15M 增至 9.76M）。

## 分析

### 1. 四個資料集全部落在誤差範圍內，沒有一個資料集從更高解析度受益

$|\Delta|$ 沒有一個超過兩邊 95% 信賴區間之和：EuroSAT +0.58pp（閾值 0.85pp）、CropDiseases -0.24pp（閾值 1.31pp）、ISIC -0.89pp（閾值 1.23pp）、ChestX +0.04pp（閾值 0.92pp）。ISIC 和 CropDiseases 甚至是負向（雖不顯著），沒有任何資料集顯示「解析度越高越好」的趨勢。

### 2. 參數量增加 61%，換不到任何可量測的準確率提升

參數增加的來源並非「更多有效計算」，而是一個架構副作用：`FeatureUpsampler` 的 `pos_embed` 和 `residual_net` 內的 `LayerNorm` 都對空間維度做仿射參數，隨 `output_size²` 二次成長（56²=3136 vs 28²=784，整整 4 倍），因此 scale 加倍會讓這部分參數暴增，而真正做特徵轉換的兩層 3×3 卷積參數量完全不隨 scale 變化。換句話說，**多出來的 3.6M 參數幾乎全部是位置編碼和正規化的仿射項，不是額外的表徵能力**——這解釋了為什麼參數量漲了但效果沒有跟著漲。

### 3. 與 0909 report 的發現形成一致的整體圖像

三個獨立的消融/敏感度實驗現在指向同一個結論：
- FeatureRefiner（Transformer 精煉層）：三個資料集一致無貢獻（0909 report）
- $\mathcal{L}_{CR}$ 的最佳權重：資料集依賴，但存在明確的甜蜜點，不是「越多越好」（0910 report）
- **上採樣密度（本報告）**：從 28×28 提高到 56×56 同樣沒有帶來提升

**FeatureSR 的增益天花板本身就落在 28×28 這個級別**，不是模型容量不夠、也不是網格不夠密——瓶頸不在這裡。這對論文是一個重要但誠實的邊界陳述：Feature-level SR 的價值來自「從 14×14 提升到某個更密的網格 + 資料集依賴的語意錨定」這個質變本身，而不是可以透過堆更多解析度或更多參數持續換取的量變。

## 結論與建議

1. **維持 28×28（scale=2）作為最終架構設定**，不需要也不應該升到 56×56——沒有實證支持，還多付 61% 的參數成本。
2. **本報告應納入論文的架構設計依據 / 消融分析**，作為「為什麼選 scale=2 而不是更高」的直接證據，呼應 0909/0910 report 一起構成完整的超參數選擇論述。
3. 由於三個獨立方向（Refiner、λ3、解析度）都已驗證完畢，FeatureSR 的架構消融分析可以視為告一段落，不需要再開新的架構維度搜索（例如更多 Refiner 層數、不同 Upsampler 設計等），除非有新的具體假設值得驗證。
4. 若未來要重啟這條線，比較值得驗證的方向是**修正 pos_embed/LayerNorm 隨 output_size² 成長的設計缺陷**本身（例如把 LayerNorm 只作用在 channel 維度而非展開的空間維度），而不是繼續往更高解析度加測——但這需要改動模組實作，屬於架構重構而非超參數調整，建議列為未來工作而非本階段任務。

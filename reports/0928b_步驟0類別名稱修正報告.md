# 步驟 0：類別名稱修正報告（2026-09-28）

`reports/0928_交接與下一步.md` 第三節步驟 0。

## 問題

`train_episodic.py` 的 prompt 直接用資料夾名稱：ISIC 是縮寫（「a photo of a MEL」），EuroSAT 是黏在一起的寫法（「a photo of a SeaLake」）。ATHA 官方程式碼（`coop_lora_trainer.py` 的 `label_names`）用的是完整名稱。

## 修改

| 檔案 | 內容 |
|:---|:---|
| `models/clip_wrapper.py` | 新增 `DISPLAY_NAMES`（名稱沿用 ATHA）與 `display_name()`；`encode_text(display_names=...)` 只在預設 prompt 路徑套用，預設 False |
| `models/clip_lora.py` | `encode_text` 轉傳 `display_names` |
| `train_episodic.py` | 新增 `--class_names full\|raw`，**預設 full**；full 的結果檔名加 `_cnfull`，raw 維持舊檔名 |
| `scripts/paired_diff.py` | 兩個 `.jsonl` 的逐 episode 配對差 ± 95% CI（會檢查兩邊類別一致，確認是同一批 episode） |
| `scripts/run_step0_classnames.sh` | 本報告的四組實驗 |

- 對照表以資料夾名稱為 key 查表，與類別順序無關；四個資料集的順序也已確認與 ATHA 一致。ChestX、CropDiseases 原本就是完整名稱，不受影響。
- `display_names` 預設 False 是因為 `train.py`、`evaluate.py` 也會傳 `dataset_name`，自動套用會悄悄改變舊實驗的行為。
- **向下相容驗證**：`--class_names raw` 跑 ISIC 5-shot 前 3 個 episode，準確率與舊結果逐 episode 完全相同（42.67 / 56.00 / 46.67）。
- **注意**：`train_episodic.py` 預設已改為 full。舊腳本（`run_episodic_baseline.sh`、`run_episodic_stage2.sh`）若不加 `--class_names raw` 重跑，會產生新的 `_cnfull` 結果檔，而不是續跑舊檔。

## 判讀

- **ISIC 兩個 shot 都升了約 2.15 分，配對 CI 都不含 0**，現在分別只比論文低 0.82、0.90，約一個 CI 寬度。0924 報告中 ISIC「系統性低約 3 分」的主因就是類別名稱。
- **EuroSAT 兩個 shot 都在雜訊內**（5-shot 的配對 CI 只有 ±0.27，可以說確實沒有影響）。推測是 `SeaLake`、`AnnualCrop` 這類寫法經 CLIP tokenizer 切開後仍大致可讀，且文字端有 LoRA 可以補償；ISIC 的縮寫則沒有語意。
- **8 組 baseline 現在都在誤差內對上論文**，不需要改用 ATHA 程式碼的設定。之後所有步驟以 `--class_names full` 的結果作為 baseline。
- **Prompt Ensemble 的歸因仍未解決**：舊協定下 EuroSAT 的 +3.64 是在文字塔凍結、評估不用 support 的條件下量到的，名稱品質在那個設定下的影響可能大得多，本實驗無法回答。要在 episodic 協定下做這個對照，需先讓 ensemble 路徑支援文字端 LoRA 的梯度（目前會直接報錯），或改用只開視覺端 LoRA 的設定。

## 與 ATHA 程式碼的剩餘差距

同樣是 ISIC 5-shot、有資料增強：ATHA 程式碼的 baseline 是 54.98，我們是 49.86，相差約 5 分。兩者設定不同（r=16/α=8、CoOp 可學習 prompt、logit scale 4、100 步、無 cosine，增強方式也未必相同），無法歸因到單一項。主實驗仍以論文標準的 CLIP-LoRA 為比較對象；若之後步驟 1 或 2 出現增益，再考慮到 ATHA 的設定上驗證一次，以回應「在更強的 baseline 上是否仍成立」。
